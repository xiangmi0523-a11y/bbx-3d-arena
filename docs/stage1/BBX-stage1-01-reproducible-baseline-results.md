## 1. 新增的测试能力

| 能力 | 位置 | 说明 |
|---|---|---|
| 随机源控制与非确定来源探测 | `tests/repro/determinism.ts` | 用种子替换 `Math.random` 并统计调用次数。同时统计 `performance.now` / `Date.now` / `crypto` 的调用；Rapier `world.step` 内部读取的计时单独计数。 |
| 四通道逐步记录 | `tests/repro/recorder.ts` | 通道为 physics（位置、四元数、线速度、角速度、转速、倾斜）、intent（状态、heading、authority、edgeW、脱困计时）、contact（接触分类、接触反馈状态）、battle（撞击事件、各项计数、僵持计时）。每个通道记一条全程哈希，另每 120 步记一个块哈希；同时保存关键帧、带步号的事件表、初始状态，并可在指定区间逐步展开完整状态。 |
| 关键参数指纹 | `tests/repro/config.ts` | 覆盖部件物理字段、BEY/INTENT/SMASH/CONTACT 调参、撞击分档、接触采样常量、步长、重力、求解器参数、场地和 Rapier 版本。 |
| 逐场对照与定位 | `tests/repro/compare.ts`、`tests/diag/repro-compare.diag.ts` | 给出第一个不同的块、该块关键帧的偏差、第一处不同的事件和终局，再用 `REPRO_DETAIL` 定位到具体步。 |
| 行为回归报警 | `tests/repro.test.ts` + `tests/fixtures/repro-golden.json` | golden 记录 180 场的摘要。常规运行比对 11 场（每组第一场）；`REPRO_FULL=1` 时比对全部 180 场。 |
| 测试辅助固定种子 | `tests/sim.ts`、`tests/diag/harness.ts`、`tests/physics.test.ts` 两处 | 默认种子由参数派生，规则在看到结果之前就已确定。`REPRO_SEED_SALT` 可整体换一组种子做稳健性抽查。 |

## 2. 重复运行一致性（180 个固定场景）

| 对照 | 四通道全程哈希 | 完整记录（含关键帧、事件、初始状态、随机报告） | 终局与步数 |
|---|---|---|---|
| 第 1 轮 vs 第 2 轮 | 180/180 | 180/180 | 180/180 |
| 第 1 轮 vs 第 3 轮 | 180/180 | 180/180 | 180/180 |
| 第 2 轮 vs 第 3 轮 | 180/180 | 180/180 | 180/180 |
| 第 1 轮 vs 逆序运行 | 180/180 | 180/180 | 180/180 |

- 每轮都是独立的 vitest 进程，耗时约 52 秒。终局分布为旋转终结 174 场、超时 6 场；共 1100 次撞击、6862 个事件。
- physics 通道与 Stage A 工具在 B1（20bef8e）上的结果对照：物理哈希、步数、终局、撞击数均为 180/180 一致。这说明新记录器只读取、不干扰物理，且与历史数据可以直接对照。
- 随机源报告（每轮相同）：
  - 搭建阶段的随机调用为每场 4 次或 8 次，全部经过种子。
  - 推进阶段 `Math.random` 调用 0 次。
  - 游戏代码读取时间或系统随机源 0 次。
  - Rapier 内部计时读取共 13,203,146 次。
- 灵敏度验证：把 `airDrag` 改了 1e-10（0.004 → 0.0040000001），30/30 场都被检测出差异，全部定位在第 0 块；逐步展开后确定第一处差异出现在第 0 步，是双方转速相差约 8e-11；其中 10 场的终局也随之改变。

## 3. 原有测试

| 运行 | 结果 |
|---|---|
| 本分支全量 vitest，三轮 | 133/137，三轮逐项（状态和失败信息）完全相同 |
| main 原样运行 physics.test（未固定种子），十轮 | 7 轮只有已知失败；2 轮多出“撞墙”失败；1 轮多出“三种类型”失败 |

本分支固定种子后有 4 个失败：

1. P2.3.1 球头僵持 15.48 s：这是原有的已知失败，结果与之前相同。
2. P2.2.1 三种类型差异，1.11 < 1.26。
3. P2.2.1 撞墙频率，1.92 > 1.2。
4. P2.1 交锋三档。

第 2–4 项在 main 上本来就随机出现。30 组种子下的通过率分别为：三种类型 19/30，撞墙 25/30，交锋三档 28/30。阈值没有修改，等统计测试改造（阶段 1 后续项）时再定。是否默认固定种子已提交产品负责人裁决。

## 5. 仍然存在的确定性限制

1. **跨平台**：只在本机（linux-x64，Node v22）验证。此前观察到 macOS arm64 有差异（贴墙频率 1.28），WASM 浮点在不同平台上是否逐位一致属于【未知】。确定性构建 `@dimforge/rapier3d-deterministic-compat@0.19.3` 尚未评估。
2. **Rapier 内部计时**：求解过程中会读取 `performance.now`，这是它的性能计数器。依据是跨进程逐位一致：这些读数不影响结果属于【推断 + 实证】，没有读源码证实。
3. **正式游戏本身不可复现**：每局的种子来自 `Math.random`，没有记录；发射力度来自手势时间。本任务按要求只在测试侧控制。
4. **测试隔离问题（只记录，未修）**：`physics.test` 的“P2.1 接近速度”用例改了 `BEY_TUNING.driveMinGrip`，但没有用 try/finally 恢复。断言一旦失败，后面的用例就会继承被改过的参数，出现连锁失败；种子扰动 19 那一轮就是这样。`headOn` 也是同样写法。
5. **非物理随机**：three.js 对象的 UUID 和 BattleCamera 构造会调用 `Math.random`（只在视觉相关测试中出现），不影响物理断言。
