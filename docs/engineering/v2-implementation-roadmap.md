## 2. 实施顺序（里程碑）

调整理由：v2.0 的 S1→S7 是严格串行；历史上项目在低速物理实验里反复打转，产品闭环一直没有成形。比赛规则、爆裂、零件数据和最小 UI 都**不依赖**运动模型的细节，只依赖接口（v2.0 §12 也允许 S6 与 S2/S3 并行），所以先把“能打完一整场比赛”的闭环建起来，物理与 AI 改进随后在同一套比赛规则下验收。设计原则与禁令全部保留。

## 3. 测试与验证体系

1. **CI 每次推送**：类型检查 → 全部单元测试 → 180 场固定种子全量回归（golden）→ 网页构建；诊断任务按 `scripts/ci-diag.sh` 运行实验并上传结果。
2. **确定性回归 ≠ 平衡结论**：golden 只回答“行为变没变”；胜率、分布结论一律用功效表样本量（10 个点差每组约 390 场）+ Wilson 95% CI，实验前写明效应量、样本量、种子集与采用 / 回退规则。
3. **行为变化的纪律**：任何改变物理 / AI / 规则的提交，在提交说明里列出变化原因与影响面，CI 先证明“只有预期的场景变化”，再重新生成 golden；改名、重构类提交必须证明四通道哈希不变。
4. **禁令守护**：不引入 stallBreak / stallRoll / 通用程序化脱困 / 瞬移 / 无约束速度注入 / 强制朝向 / 脚本假碰撞；`motion.test` 已有“发射后只施加有上限的冲量、不设置速度或位置”的检查，继续保留并扩展。
5. **不以单元测试代替体验验收**：每个里程碑附固定种子录像 / 截图与指标表；体验结论由真机验收给出。

## 4. 风险与控制

| 风险 | 等级 | 控制 |
|---|---|---|
| 球头 / 针尖低速僵持在 M4 的 A/B 中两种实现都不达标 | 高 | 先定位根因（进动增速 vs 滚阻 vs 碗面中心梯度），逐项消融；不加脚本兜底；比赛规则的 60 s 回合上限保证僵持最多导致一次自转终结 |
| 爆裂 k 标定后某一类型被系统性爆裂（F7） | 中 | 分 Bit / 分构筑报告爆裂率；只调 burstGuard 初值，不改公式结构 |
| 改名（Disc→Ratchet、Tip→Bit）牵动 40 余个文件 | 中 | 单独提交 + 四通道哈希不变证明 + 存档迁移测试 |
| 本环境无法本地跑物理 | 中 | CI 作为唯一的物理验证；每轮实验一次性设计完整，减少往返 |
| 能量账本 E7 未完成 | 低 | 本路线不引入任何“自转转化为伤害”的机制；爆裂只用实测冲量；E7 在 M4 期间作为诊断项完成 |
