## 0. 审查目标、方法、工具与限制

### 0.1 最终产品目标（审查的“高度”基准）

BBX 的最终形态是：**一款完整、自然、有竞技感、稳定流畅的离线单人 3D 陀螺对战游戏**。拆成可检验的产品条件：

| 产品条件 | 含义 | 当前状态（详见 C 部分） |
|---|---|---|
| T1 自然的自主运动 | 任何合法组装发射后都会在碗内持续移动、交锋，不会长时间原地不动 | **未达到**：针尖无自主运动；球头对球头最长僵持 15.5 s（测试实测） |
| T2 有意义的碰撞 | 撞击有重量感，攻击/防御/耐力在碰撞中表现不同 | **部分达到**：有分级反馈；但攻防在物理上对称、持续接触无推挤 |
| T3 组装有策略 | 换件能产生玩家可理解、可预期的强弱差异 | **部分达到**：差异主要来自 tip 的 gearGrip/摩擦与质量；rimWeight 只生效一半；攻防属性语义未实现 |
| T4 竞技闭环 | 赛制、终结类型、对手、进度 | **未达到**：单局、无爆裂、单一对手 |
| T5 稳定流畅 | iPhone 稳定 60 fps，不随时间掉档 | **未达到**：真机稳态约 47 fps，GPU 侧受限 |
| T6 可持续开发 | 有可信主线、可复现、测试能拦截回归 | **未达到**：main 为空、PR 链未合并、1 个已知失败测试 |

### A.5 质量门（V1 树上实测）

- **【事实】** `tsc --noEmit` 通过。

### B.3 核心闭环：AI → 意图 → 控制 → 运动 → 碰撞 → 状态 → AI

| 环节 | 实际实现（文件:行） | 输出 / 状态 |
|---|---|---|
| ① AI 状态识别 | `motionIntent.ts:237-291`：按中心距判定 touching（`d < bladeSum + 0.03`），按状态计时与随机决策 | `state`（launch/roam/orbit/cut/contact/disengage/guard/evade/breakout） |
| ② 运动意图 | `motionIntent.ts:296-465`：期望速度 → 误差方向 | `heading`（期望牵引方向）、`authority`（0–0.9）、`edgeW` |
| ③ 物理控制 | `BeyPhysics.ts:447-501, 528-535`：**只有 driveGrip ≥ 0.2 时**才施加牵引冲量；authority 只改变进动相位的**转速**：`rate *= 1 − a·cosΔ` | 牵引冲量（大小与 AI 无关）、进动相位 |
| ④ 实际运动 | Rapier：重力 + 碗面 + 倾斜球头摩擦；脚本：牵引冲量、轨道冲刺、滚阻冲量、自稳 PD | 位置、速度、倾斜 |
| ⑤ 碰撞响应 | Rapier 接触求解 + `BattleSystem.resolveSmash`（只在 Rapier“开始接触”事件、冷却 0.07 s） | 冲量、掉速、ImpactEvent |
| ⑥ 状态变化 | `knockResync`：被撞歪后进动相位跟随实际倾斜；`watchStall` 强制 breakout | 新的相位/breakout |
| ⑦ AI 再决策 | 下一步 ① 读位置/速度/转速比 | — |

**闭环的关键断点（【事实】）：**
1. **AI 对针尖轴心几乎没有出口。** 针尖 `gearGrip = 0.1 < driveMinGrip 0.2`，第 451 行的牵引分支整个不进入，`steering` 恒为 0，authority 不影响任何东西。只有墙边借用 `edgeGrip` 时才有极弱作用。即：**对针尖陀螺，AI 的全部决策只是日志。**
2. **AI 只能控制“方向的停留时间”，不能控制力的大小。** 牵引大小由 `driveAccel × driveGrip × 转速比` 决定，AI 无法加速、减速或刹车（刹车只能间接通过“牵引指向反方向”）。
3. **AI 与物理用的“接触”定义不同**（见 D.1）。

### C1 物理动力学

**当前实现**
- Rapier 0.19.3，`GRAVITY = −20`，120 Hz，8 次求解迭代（`PhysicsWorld.ts:15-44`）。
- 陀螺是一个刚体 + 4 个碰撞体（球 + 轴杆 + Disc 圆柱 + Blade 圆柱），**不模拟陀螺效应**；转速大小、倾斜、进动全部由 `BeyPhysics.preStep` 每步读出角速度、修改、再 `setAngvel` 写回（`:372-567`）。
- 额外施加的脚本力：轨道冲刺、轴心牵引、滚动阻力、刀刃咬合冲量、脱困牵引、转速衰减（恒定 + 空气 + 刮地 + 牵引/转向消耗）。

**已确认缺陷**
| # | 缺陷 | 证据 | 可信度 |
|---|---|---|---|
| P-1 | **两套互相矛盾的转动惯量。** 脚本掉速、撞击掉速用 `spec.spinInertia`（含 rimWeight，`assemble.ts:179-182`）；Rapier 接触摩擦力矩、撞后摆动用的是 `setMass` + 形状自动推出的惯量（`BeyPhysics.ts:216-242`；Rapier 官方文档：“angular inertia … computed automatically based on its shape and this mass”）。实测：耐力型「泰坦王冠」脚本 0.75 vs Rapier 0.50（**只有 67%**），平衡/防御型 92%，攻击型 100%。含义：同样的刀刃接触摩擦，在 Rapier 里耐力型掉的转速比设计值多约 50%——**耐力型的核心优势在碰撞中被削弱，而攻击型不受影响** | 代码 + 官方文档 + 0.3 测量 | 事实 |
| P-2 | **陀螺仪自稳是一个 PD 弹簧**（刚度 320、阻尼 32×s），把轴拉向“由进动相位决定的目标倾斜”，被撞的倾斜被当作误差直接阻尼掉，而不是转化为进动。碰撞后的姿态变化因此被系统性压扁 | `:519-561` | 事实（机制）；对手感的影响为推断 |
| P-3 | **进动相位是一个独立积分的脚本变量**（基速 3 rad/s + 80/ω），不是由重力力矩与角动量算出；它同时驱动倾斜目标和牵引方向。注释说“由 Rapier 摩擦自然产生花瓣轨迹”，但实际同时还有显式牵引冲量（`:495-496`）。**推导**：按刚体进动公式 Ω = m·g·h/(I·ω)，默认攻击组合 m≈4.45、质心高 h≈0.39、g=20、I≈0.465、ω=150 rad/s → Ω≈0.50 rad/s；脚本值为 3+80/150≈3.53 rad/s，约 **7 倍**。牵引方向因此每 ~1.8 s 转一整圈，一圈内的牵引冲量矢量和接近 0，净位移只剩 AI 偏置那一部分（球头 ≤0.26、针尖 0） | 代码 + 推导 | 事实（数值）；“导致净移动弱”为推断 |
| P-4 | **单位与时间尺度不一致**：场地半径 5.4、刀刃半径 ~0.5（比例接近真实），重力只取 −20，转速 ~100–170 rad/s、移动 2–10 m/s。尺度没有统一换算，导致大量“手调常数”去补偿（precessBase、driveAccel、rollBase 等） | 常数 | 推断 |
| P-5 | **滚动阻力是恒定脚本减速度**（`(0.02+0.02·μ)·20 ≈ 0.45 m/s²`），与接触点、法向力、转速无关。它会吃掉针尖原生摩擦产生的微小漂移——这正是 V1 要打补丁的对象 | `:503-514` | 事实 |
| P-6 | `grounded` 用解析剖面 `floorHeight(r)` 而不是真实接触；口袋内 `floorY = −∞` → 永远不 grounded | `:379-382` | 事实，影响小 |
| P-7 | 初始进动相位 `Math.random()`（`:168`）、对手发射 `Math.random`（`launch.ts:57`），游戏本体不可复现；测试靠覆盖全局 `Math.random` | 代码 | 事实 |

**潜在架构问题**：物理真相被分成三份——Rapier 状态、BeyPhysics 私有状态（precession、spin、breakout、rollScale）、spec 里的派生参数。任何一份改动都可能和另两份脱节（P-1 就是例子）。

### C2 自主运动

**当前实现**：运动 = 进动相位决定方向的轴心牵引 + 碗面重力 + Rapier 摩擦 + 滚阻；AI 通过调节进动相位转速让牵引“更多时间”指向期望方向（`motionIntent.ts` 文件头；`BeyPhysics.ts:528-535`）。理论平均偏置仅 `(1−√(1−a²))/a`，a=0.9 时约 0.63。

## D. 跨系统问题

### D.1 共同根因一：运动没有统一的“驱动模型”

M-1、M-2、M-3、M-4、AI-1、AR-1、以及整个低速停滞系列（探针、R1c、E1/E2、E5、V1）都指向同一个设计：

> **陀螺的自主移动 = 一个脚本化进动相位 × 一个由 gearGrip 门控、大小固定的牵引冲量 − 一个恒定滚阻。**

- 针尖没有牵引 → AI 失效 → 只能靠原生摩擦漂移 → 被恒定滚阻吃掉 → 停滞 → 加 V1 降滚阻 / R1c 加恢复通道。
- 球头牵引弱 → 关闭通用脱困后长僵持（15.5 s 失败用例）。
- 平底/橡胶牵引强 → 需要墙边保护、launch 初相、切向抵消等一系列 AI 修正。

这些问题**不能单独修**：给针尖单独调滚阻（V1）不会让 AI 生效；给 AI 加更多状态也不会让没有牵引的轴心动起来。**【推断，高可信；与 E1/E2/E5-A/V1 报告的结论一致】**

### D.2 共同根因二：“接触”有五种互不一致的定义

| 使用方 | 判定方式 |
|---|---|
| resolveSmash | Rapier 碰撞**开始**事件（任意碰撞体对）+ 0.07 s 冷却 |
| ContactFeedback / V1 门控 | Stage A 证据：solver 距离 ≤ 0 或法向冲量 > 0 |
| MotionIntent | 质心水平距离 < 刀刃半径和 + 0.03 |
| isDeathWobble | 质心水平距离 < 刀刃半径和 + 0.05 |
| watchStall（已关） | 质心距离 < 外径和 + 0.4 |

同一步里，AI 可以认为在接触、反馈认为没接触、咬合冲量又因为不是“开始”而不结算。C-1、C-2、AI-3 与 Stage A 前的观测问题都源于此。**【事实】**

### D.3 共同根因三：物理状态被多方写入

`setAngvel` 每步覆盖（BeyPhysics）、`loseSpin`/`applyImpulseAtPoint`（BattleSystem）、`rollScale`/`breakout`（BattleSystem → BeyPhysics）、`forceBreakout`（BattleSystem → Intent）、`knockResync`（物理 → 相位）。没有“一步之内谁先谁后、谁拥有哪项状态”的契约，导致每加一个机制都要靠逐步 hash 比对来证明没有副作用（Stage A、V1、R1c 都在做这件事）。**【事实】**

### D.4 共同根因四：部件属性与物理效果脱节

attack/defense 对称（C-4）、rimWeight 只进脚本（P-1）、gearGrip 一参两义（M-1）、burstResistance 无用（B-2）、展示属性独立推算（B-3）。结果是“组装”这一核心玩法在物理上的区分度主要来自 tip 的 gearGrip/friction 和总质量，而不是玩家能理解的属性。G-5（攻击型赢不了）至少部分来自这里。**【推断，中高可信】**

### D.5 模块互相影响关系

```
部件属性 ──┬─> 物理参数（质量/摩擦/gearGrip/惯量×2）──> 运动 ──> 碰撞 ──> 胜负
           └─> AI 画像 ──> heading/authority ──┘（被 gearGrip 门控）
场地常数 ──> 物理几何 + AI 墙边阈值 + 镜头 + 发射点
接触定义×5 ──> 咬合冲量 / 反馈 / AI 状态 / 死亡摇摆 / V1 门控
画质 ──> GPU 负载（与物理无关；CPU 仅约 3 ms）
```

### D.6 不能单独修复的问题

- 低速停滞（针尖、球头）——依赖 D.1。
- AI 行为质量——依赖 D.1 与 D.2。
- 攻防平衡/攻击型胜率——依赖 D.4 与 C-1（持续接触无推挤）。
- 碰撞“重量感”——依赖 P-2（自稳 PD 吞掉姿态变化）与 C-2（法线/力矩臂不准）。

### D.7 可以独立处理的问题

画质阶梯（R-1）、画质锁定存档（R-3）、Haptics（R-4）、发射倾角（G-3）、PR/分支治理（A 部分）、研究数据外移（E-5）、关闭开关的死代码清理（M-5）。

### D.8 反证检验（主动寻找推翻结论的证据）

| 结论 | 可能推翻它的证据 | 检验结果 |
|---|---|---|
| D.1 运动问题源于驱动模型，而非某个参数 | 如果“只开放针尖牵引门槛”就能解决停滞，则是参数问题 | **【报告】** E2：把门槛打开让针尖获得牵引后，98% 的窗口仍然停滞；V1：滚阻 ×0.5 后 10 s 低速占比仍 100%。两个单参数反事实都失败 → 结论**未被推翻** |
| 针尖 AI 无效 | 墙边借用 edgeGrip、或 heading 在别处被使用 | edgeGrip 只在外圈生效且仅在与墙边修正夹角 < 90° 时出力；heading 仅用于该判断。碗中央无任何出口。E5 报告独立得出“authority 只在牵引门内读取” → **未被推翻** |
| 攻防在碰撞中对称（C-4） | 刀刃摩擦/恢复系数按刀刃不同，可能给攻击型非对称优势 | Rapier 默认组合规则（Average）对一对碰撞体也是对称的；唯一非对称的是质量 → **未被推翻**，但“攻击型输”的原因不止这一条（转速经济、P-1 也起作用），所以只把它列为原因之一 |
| P-1 惯量双源影响平衡 | 如果 Rapier 接触摩擦力矩对转速的影响很小，双源就无关紧要 | 每步 `mag` 从 Rapier 求解后的角速度读出，接触摩擦力矩会进入转速；但其**量级**本轮没测 → 影响大小标【推断】 |
| 帧率瓶颈在 GPU | CPU 也可能在某些时刻成为瓶颈（例如 CCD 尖峰） | **【报告】** 所有 >1 ms 物理步都在 CCD 开启时（占 7%），说明存在 CPU 尖峰；但 Stage 0 平均 CPU 仅约 3 ms/帧、unattributed 约 18 ms → 稳态仍以 GPU/合成为主，CPU 尖峰是次要问题 |
| 球头长僵持与针尖同因 | 球头有牵引（0.3 表：可进分支、偏置 0.26），理论上能走 | **部分推翻**：球头的成因不能简单等同于“无牵引”。推断为：进动过快使牵引矢量和接近 0 + 接触状态下双方 contact 意图互推 + 关闭通用脱困。此项列为【未知】的细节，但不影响“需要重新设计驱动模型”的决策 |

### D.9 已尝试方案的成败与原因

| 方案（提交） | 目标 | 结果 | 成败原因（与本审查根因的对应） |
|---|---|---|---|

| E1/E2 7aa5975 | 力分解、门槛反事实 | 漂移来自针尖自转滑移摩擦；开门槛仍 98% 停滞【报告】 | 证明问题不在单一门槛 |

## F. 优先级

### P0：阻碍核心玩法或导致严重错误
1. **运动驱动模型缺陷（D.1）**：针尖完全无自主运动、AI 对其失效；球头对球头最长僵持 15.5 s（主干测试失败）。核心玩法“自动对战”在这些组合下不成立。
2. **主线不清（A）**：main 为空，8 个叠加 PR 未合并，后续 9 个提交无 PR，实验分支与正式分支混在一起。任何正式改进都缺少可信基线。

### P1：明显损害核心体验
3. 攻防在碰撞中对称、持续接触无推挤（C-4、C-1）→ 攻击型难赢、组装区分度弱。
4. 接触定义不一致（D.2）→ AI、反馈、规则互相矛盾。
5. 自稳 PD 吞掉碰撞姿态变化 + 法线/力矩臂估算（P-2、C-2）→ 撞击缺重量感、撞后轨迹失真。
6. GPU 侧帧率：最低档仍 2x+阴影+MSAA，真机稳态约 47 fps（R-1）。
7. 转动惯量双源（P-1）→ 耐力型配重的物理意义只有一半。

### P2：影响完整性、稳定性或扩展能力
8. 产品系统缺失：赛制、对手列表/难度、爆裂终结、回合间换件（G-1、G-2）。
9. GameEngine 上帝类、跨模块写状态、调参无分层（E-1、E-2、E-3）。
10. 测试以统计为主、缺物理契约测试，存在已知失败与偶发失败，CI 不跑测试，跨平台数值差异未查（E-4、E-6）。
11. 视觉/碰撞体尺寸不一致（C-5），旧 Blade 与新 Disc 穿插、材质预算超标（B-6）。
12. 游戏本体不可复现（P-7），诊断工具未进主干（E-7）。

### P3：体验优化与非关键事项
13. 画质锁定持久化、Haptics、发射倾角、左旋部件、HUD rpm 展示口径、研究数据外移、死代码清理。

## G. 证据缺口（仅列真正妨碍决策的）

1. **新驱动模型的真机手感目标值**：多快算“积极”、多久算“僵持”、攻击型对耐力型应有多少胜率。代码只能告诉我们现状，无法告诉我们目标；这需要产品负责人给出数值或参照视频。没有它，重新设计无法验收。
2. **GPU 负载的构成**：浏览器/WKWebView 不提供 GPU 计时，现有数据只能证明“不是 CPU”。阴影、MSAA、像素比、透明材质各占多少，只能在真机上逐项 A/B（需要诊断面板进入主干或单独测试包）。
3. **跨平台物理差异**（macOS arm64 vs Linux 测试结果不同）：是否影响确定性回放、是否影响真机行为，无法从代码判断，需一次对照运行。

其余问题（D.1–D.4、C-4、P-1、R-1 的配置事实等）**已经可以凭代码作出决策**，不需要更多实验。

## 结论摘要

**已经可以直接作出决策的**
- 陀螺运动驱动模型需要重新设计，V1 与 R1c 不进入正式主线（D.1、E）。
- 统一接触定义、统一转动惯量、AI 与物理解耦属于必要重构（D.2、P-1、AI-2）。
- 碰撞中攻防对称是代码事实，必须改为非对称（C-4）。
- 最低画质档需要新增更低的 GPU 档位（R-1）。
- 主线治理先于一切功能改动（A、P0-2）。
