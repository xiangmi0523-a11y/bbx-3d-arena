# BBX 低速停滞系统：Stage B，R1c 受控恢复实验报告

- 分支：`feat/low-speed-stall-r1c`，基线是 Stage A 提交 `2f573ab`。Stage A 分支和 main 都没有改动。
- 标注：**[实测]** 表示由本次固定种子运行直接得到；**[推断]** 表示由数据推理得出，没有单独验证；**[未验证]** 表示没有测量。
- 数据汇总：[eval.md](eval.md)，由 `scripts/r1c-eval.mjs` 从原始 runs.json 生成。全部 24 场针尖对针尖都列出，包括失败场次，每次恢复也都有一行。

## 0. 结论

1. **R1c 能让两台陀螺重新接触，但没有恢复自然、持续的自主运动。** [实测]
   - 135 次恢复中，有 116 次在 3 s 内重新出现几何接触，P50 用时 0.24 s。
   - 但启动后 3 s 的净位移 P50 只有 0.059 m，启动前 3 s 是 0.037 m，两者是同一量级。
   - 接触结束后，两台陀螺很快回到原地低速状态。
2. **按整体指标看，改善很小。**
   - [实测] 24 场针尖对针尖的低速占比从 92.8% 降到 89.2%，低速总时长从 1676 s 降到 1603 s。
   - [实测] 最长低速段 P50 从 63.8 s 降到 33.1 s。
   - [推断] 最长低速段变短，主要是因为僵持被每 6 s 一次的轻推切成了几段，不是因为陀螺恢复了运动。
3. **出现了周期性的"推一下、碰一下、再停住"。** [实测]
   - 同场相邻两次恢复的间隔 P50 是 6.02 s，P90 是 6.03 s，正好等于冷却 3 s 加 dwell 3 s。
   - [推断] 这是辅助节律，不是自然运动。在画面上很可能显得机械，这一点 [未验证]，没有在真机或录像里看过。
4. **最大的未覆盖区是转速比例低于 0.4 以后。**
   - [实测] B 中 44.4% 的低速时间处在转速比例 < 0.4 的阶段。按设计这一段交给原有终局机制，R1c 不介入。
   - [推断] 每场最长的低速段都在最后一次恢复之后开始，并一直持续到对局结束。
5. **R1c 本身的运动是温和的，没有出现强制分离。** [实测]
   - 恢复期间最大水平速度 0.69 m/s，正常对局的速度峰值是 4.8 到 7.9 m/s。
   - 启动后 3 s 内最大半径 0.73 m，贴墙步数为 0。
   - 每次施力方向与拦截方向的夹角都小于 90°，没有朝远离对手的方向推。
6. **按要求，我没有加大控制力度去制造更好的数字。** 下一步怎么走（保留、调整或放弃 R1c）由架构审查决定。

## 2. R1c 状态流转

```
             分类成立                      持续 dwellTime(3 s) 且
   ┌──────┐ ─────────▶ ┌───────┐ ───────── 期间净位移 ≤ 0.4 m ─────▶ ┌────────┐
   │ idle │            │ dwell │                                      │ active │
   └──────┘ ◀───────── └───────┘                                      └────────┘
      ▲      分类失败      │ 期间净位移 > 0.4 m：dwell 重新计时          │
      │                    ▼                                            │ 任一退出条件
      │                 (dwell)                                         ▼
      │                                   冷却 3 s                ┌──────────┐
      └────────────────────────────────────────────────────────── │ cooldown │
                                                                  └──────────┘
```

**分类条件。** 以下全部成立才进入 dwell，按这个顺序检查，不成立的第一条记录为 `reject`：
1. `tip`：双方 gearGrip 都低于牵引门槛 driveMinGrip，即针尖对针尖。
2. `motionState`：双方都着地，且都不在冲刺、脱困或发射阶段。
3. `traction`：本步双方都没有实际施加轴心牵引。这一条用来表示"有效牵引失效"。
4. `speed`：双方水平速度都低于 0.4 m/s。
5. `contact`：上一步既没有几何接触，也没有冲量响应。
6. `wobble`：没有 wobble 计时。
7. `lowSpin`：双方转速比例都不低于 0.4。
8. `spinImbalance`：转速比 max/min 不超过 1.5。
9. `gap`：刀刃间隙不超过 0.25 m。**不要求真实接触。**

**active 每步先检查退出，再决定是否施力。** 退出条件按以下顺序检查：

| 退出原因 | 条件 |
|---|---|
| `invalid` | 位置或速度出现 NaN，或者间隙大于 0.5 m |
| `contact` | Stage A 观测到几何接触 |
| `wobble` | wobble 计时开始，或 wobble 次数增加 |
| `timeout` | active 持续达到 1.5 s |
| `budget` | 双方累计 Δv 都达到 1.0 m/s |
| `unclassified` | 陀尖、着地、冲刺、脱困、转速比例或转速平衡任一条件不再成立 |
| `moved` | 启动以来任一台的净位移超过 0.25 m |

不论哪种原因退出，都先进入 3 s 冷却。

**施力方式。** 每台陀螺每步计算一次：
1. 拦截点 = 对手位置 + 对手速度 × 提前量。提前量 = min(0.5 s, 距离 / 0.6)。
2. 从自然进动给出的牵引方向出发，朝拦截点**最多偏转 30°**（maxBias）。施力方向始终由自然进动决定，R1c 只做有界的偏置。
3. 偏转后如果仍然和拦截方向成 90° 以上，这一步不施力。
4. 沿施力方向的速度已经达到 0.6 m/s 时，也不施力。
5. 否则施加 Δv = min(maxAccel 4 m/s², 原牵引加速度 driveAccel × edgeGrip × 转速比例) × dt。结果再被两项截断：离速度上限 0.6 m/s 还差的部分，以及累计 Δv 剩余的预算。
6. 转速消耗按原牵引规则计算：driveSpinCost × 等效咬合 × 惯量系数 × dt。

**不是固定的反向推力。**
- [实测] 两台各自朝对手的拦截点轻推，方向随自然进动连续变化。
- [实测] 在施过力的步上，偏置方向与拦截方向的夹角最大小于 90°。
- [实测] 按全部 active 步平均，偏置夹角 P50 是 68°，自然方向夹角 P50 是 95°。全部步的平均值 P90 可以超过 90°，因为其中含有不施力的步，第 3 条规则会在这些步上跳过施力。

## 3. 关键阈值和数据依据

数据来自探针 V2：同一套 180 场矩阵和种子，在 cb4c2c4 上测得。Stage A 证明物理不变。

| 参数 | 值 | 依据 |
|---|---|---|
| slowSpeed | 0.4 m/s | 与 V2 的 WATCH(0.4) 口径相同。 |
| dwellTime | 3 s | V2 针尖对针尖低速段：持续到 2 s 的有 25 段，其中 24 段最终 ≥ 10 s；持续到 3 s 的 24 段全部 ≥ 10 s，即 0 误判。 |
| dwellNetMax | 0.4 m | V2 长停滞段的 3 s 净位移最大 0.354 m。 |
| minSpinRatio | 0.4 | V2 长停滞开始时转速比例 ≥ 0.74。低于 0.4 交给终局机制，不和 wobble 抢。 |
| maxSpinImbalance | 1.5 | V2 长停滞开始时 spinA/B 在 0.91 到 1.28 之间。 |
| maxGap | 0.25 m | V2 候选间隙 P90 0.084 m，最大 0.22 m。 |
| maxBias | 30° | 有界偏置，保留自然进动作为主导方向。[推断] 没有扫描对比其他值。 |
| maxAccel | 4 m/s² | 低于原牵引在 edgeGrip 0.3 下的上限 30 × 0.3 = 9 m/s²。 |
| maxSpeed | 0.6 m/s | 与 slowSpeed 同量级。目的只是让两台靠近，不制造撞击。 |
| maxTime | 1.5 s | V2 中 R1a 反事实的重新接触时间 P90 约 1.6 s。 |
| maxDeltaV | 1.0 m/s，每台每次 | 与 maxSpeed 一起限制累计效果。 |
| cooldown | 3 s | 防止连续施力。 |
| movedNet | 0.25 m | 超过 V2 停滞段 3 s 净位移的 P90，视为已恢复运动。 |

[未验证] 以上参数都没有做敏感性扫描，本阶段只跑了这一组。

## 4. A/B 固定种子对照

设置：A 是 R1c 关闭（`R1C='{"enabled":0}'`），B 是默认开启。两边都是 180 场、相同种子、真实 Rapier。

### 4.1 物理隔离 [实测]
- A 与 Stage A / cb4c2c4 基线逐步状态 hash **180/180 一致**，见 `data/verify-A-vs-stageA.json`。R1c 关闭时物理与 Stage A 完全相同。
- B 与 A：156 场一致，24 场不同。不同的 24 场**正好是全部针尖对针尖场次**，非针尖对针尖场次中没有任何一场变化，见 `data/verify-B-vs-A.json`。
- 非针尖对针尖的 156 场里，R1c 的启动次数是 0。测试另外确认 BvB、SvA、AvD、球头对球头整场都没有进入 dwell。

### 4.2 十类指标

都是 24 场针尖对针尖的数据。逐场明细见 eval.md 第 2 节。

| # | 指标 | A | B | 说明 |
|---|---|---|---|---|
| 1 | 低速总时长 / 占比 | 1676 s / 92.8% | 1603 s / 89.2% | [实测] 改善 3.6 个百分点 |
| 2 | 最长低速段 P50 / P90 / max | 63.8 / 87.9 / 88.2 s | 33.1 / 49.7 / 52.7 s | [实测] 被切段，不是恢复运动 |
| 3 | 几何接触段（合计） | 137 | 250 | [实测] 每次恢复带来一次轻接触 |
| 4 | 撞击事件（合计） | 38 | 94 | [实测] |
| 5 | 启动后 3 s 净位移 P50（每台） | — | 0.059 m（启动前 3 s 为 0.037 m） | [实测] 没有持续位移 |
| 6 | 恢复期间 / 启动后 3 s 最大速度 | — | 0.69 / 0.98 m/s | [实测] 温和 |
| 7 | 贴墙步、启动后 3 s 最大半径 | 0 / — | 0 / 0.73 m | [实测] 没有被推向墙 |
| 8 | 对局结果 | 18 场 player:spin，6 场超时 | 完全相同 | [实测] 胜负与终局方式都没变 |
| 9 | 对局时长合计 | 1807 s | 1798 s | [实测] 单场有长有短，FEELSTA#3000 从 91.8 s 变成 102.3 s |

- 退出原因 [实测]：contact 98 次，budget 34 次，unclassified 3 次；没有 timeout、invalid、wobble 或 moved。
- 132 次恢复在启动时间隙 > 0，也就是没有接触时就进入了恢复，符合"不要求真实接触"。
- [实测] **没有一次以 `moved` 退出。** 也就是说，没有一次在恢复期间达到"任一台净位移超过 0.25 m"。这是"没有恢复自主运动"最直接的证据。

### 4.3 B 中的低速时间落在哪里 [实测]

24 场合计：

| 所处状态 | 占比 |
|---|---|
| 转速比例 < 0.4（lowSpin，不介入区） | 44.4% |
| dwell 计时中 | 27.7% |
| 冷却中 | 24.7% |
| active | 2.1% |
| 转速不平衡 | 0.7% |
| 间隙超限 | 0.3% |
| 其余 | < 0.3% |

[推断] 即使 R1c 能把它覆盖的那一段（dwell、冷却、active，约 54.5%）完全消掉，低速占比也只能降到约 40%。现在的问题不在恢复力度，而在两台陀螺接触之后没有自己的运动来源。在针尖对针尖下，gearGrip 0.1 低于牵引门槛 0.2，自然进动只改变方向，不产生位移。这和 V2 的结论一致。

### 4.4 失败场次

按"启动后 3 s 内重新接触"算，共 19 次失败，分布在 11 场里，全部列在 eval.md 第 3 节的全表中，接触用时一列为"–"。最多的是：
- NNPOW 0.9#3：4 次
- FEELSTA#3000：3 次
- NNPOW 0.9#0、CTRL center NN#0、CTRL graze NN#0：各 2 次

[实测] 这 19 次失败中，自然方向与拦截方向夹角均值的中位数是 122°；成功的 116 次是 91°。
[推断] 夹角接近反向时，30° 的偏置推不动两台陀螺相互靠近，预算耗尽后以 budget 退出。34 次 budget 退出的自然夹角中位数是 113°。

按"恢复自然运动"的标准算，24 场全部失败。

## 5. 是否依赖不自然的强制运动

- [实测] 没有。速度上限 0.6 m/s 远低于正常对局速度，施力方向由自然进动决定，没有固定的反向推力，没有分离动作，wobble 机制没变。
- [推断] 但周期 6 s 的"推、碰、停"节律本身可能显得不自然。原因是每次恢复都以 contact 退出，紧接着进入冷却，冷却结束后又满足分类条件。
- [未验证] 画面观感，因为没有录像，也没有真机。

## 6. 类型检查和测试

- `npx tsc --noEmit`：通过 [实测]。
- `tests/stallRecovery.test.ts`：5/5 通过 [实测]。

  2. 只针对针尖对针尖：BvB#4、SvA#1、AvD#1、CTRL center BB#0 整场都不进入 dwell。
  3. 上限与方向：施力方向和拦截方向的点积 > 0；时长、累计 Δv、速度不超上限；两次启动之间至少隔冷却加 dwell。
  4. 进入恢复不要求接触，启动前已持续 dwellTime。
  5. 转速比例低于下限后不再启动。
- 全量测试：137 项中 136 项通过，1 项失败 [实测]。
  - 失败项是 `physics.test` P2.3.1 球头对球头用例，结果 15.483 s。

## 7. 已知问题和未覆盖场景

1. 转速比例 < 0.4 的阶段不介入，占 B 低速时间的 44.4%，是按设计留给终局机制的。
2. 周期性节律：冷却加 dwell 每 6 s 重复一次。
3. 自然方向与拦截方向接近反向时，30° 偏置无效，表现为 budget 退出。
4. 参数没有做敏感性扫描。
5. 不在本阶段范围内，没有处理：球头对球头、壁面停滞、持续轻微擦碰。
6. 只在桌面 Node 环境的 Rapier 中测过。[未验证] iPhone 真机、画面观感、性能影响；R1c 每步是常数开销，没有测量。
7. R1c 读取的是上一步的接触观测（Stage A），所以 contact 退出比实际接触晚一步，约 16.7 ms。

## 8. 复现步骤

```bash
git checkout feat/low-speed-stall-r1c && npm ci
# A（R1c 关闭）和 B（默认开启）
R1C='{"enabled":0}' R1C_VERSION=A npx vitest run tests/diag/r1c.diag.ts --config vitest.diag.config.ts
R1C_VERSION=B npx vitest run tests/diag/r1c.diag.ts --config vitest.diag.config.ts
# hash 校验：A 对比 Stage A 基线（基线文件生成方法见 research/stallprobe2/）；B 对比 A

```
