## 结论摘要

1. **E5 失败的根因**：authority 只在牵引门代码块里被读取（第 482 行在第 449 行的 `if` 内），针尖 gearGrip 0.1 < driveMinGrip 0.2，确认僵持中门打开 0 步，所以 `steering` 恒为 0，进动转速调制（第 527–531 行）从未执行。实测确认僵持期间“实际进动转速 / 自然进动转速”所有分位数都等于 1.0000。[代码证据 + 实测]
2. **三条路径都不是“安全且有效”的**。在“只作用于进动、不施力、不碰门槛与摩擦”的约束下，只有 **路径 A（独立的、状态门控的进动转速偏置）** 在机制上是隔离的、可用 hash 证明不影响正常对局的；路径 B 风险明显更高；路径 C 实际上不独立，加上门控后就退化成 A。
3. **但 A 的预期效果存疑，不建议把它当作修复方案推荐**，只能作为“验证该作用链是否存在”的诊断入口：已有数据显示针尖僵持时，碗面法线造成的相对倾斜（P50 0.035 rad）大于可控的轴倾斜（P50 0.020 rad），实际倾斜方向跟随目标方向的误差 P50 35°、P90 92°，摩擦方向与“由相对倾斜预测的方向”的误差 P50 44°。即使偏置完美进入进动，能转化为水平运动方向的比例可能很低。[实测 + 物理假设]
4. 是否进行 A 的诊断实验，需要架构决定，因为它必然引入一个新的控制变量（偏置方向与强度），本任务禁止我自行创建。

## 1. 三个概念与它们之间的传递机制

| 概念 | 代码中的变量 | 谁决定它 |
|---|---|---|
| 意图方向 | `intent.heading`（motionIntent.ts，= 期望速度 − 当前速度的方向） | AI 意图状态机 |
| 倾斜方向 | 目标：`this.precession`（第 548–550 行的目标向量方位角）；实际：刚体 `up` 向量的方位角 | 进动相位积分 + 自稳控制 + Rapier 动力学 |
| 水平运动方向 | 刚体线速度 `body.linvel()` 的水平分量 | Rapier：重力沿碗面分量 + 接触摩擦 + 碰撞 + 显式冲量 |

传递链（现有代码中，针尖在牵引门外时）：

```
intent.heading ──(×，steering=0，第 482/527 行)──▶ precession 转速
precession ──(第 548–556 行：目标倾斜向量 → px/pz 回正角速度)──▶ setAngvel（第 560–563 行）
setAngvel ──(Rapier 积分)──▶ 实际轴倾斜 up
实际轴倾斜 + 碗面法线 ──(接触点偏离转轴 → 自转滑移 → Rapier 库仑摩擦)──▶ 水平力
水平力 + 碗面重力分量 + 滚动阻力冲量（第 502–510 行）──▶ 水平速度
```

- 第一环在僵持中是断的（E5 根因）。[代码证据]
- 第二、三环：`setAngvel` 只设定角速度，没有任何线速度写入。[代码证据]
- 第四环：设倾斜方向为 t̂、相对倾角为 θ，接触点相对转轴偏移约 rc·θ·t̂（rc ≈ 0.045 m），自转引起的滑移速度 ≈ ω·rc·θ·(ŷ×t̂)，摩擦方向因此为 spinSign·(−sin p, cos p)，正好就是代码第 452–453 行“自然牵引方向”。数值上被 μ·法向力 封顶（μ = 0.06 → 约 1.2 m/s²）。[物理假设，E1 已测得自转滑移是僵持中唯一的正功来源，见 e1e2 报告]
- 关键点：**决定摩擦方向的是“轴相对碗面法线”的相对倾斜，不是轴本身的倾斜**。碗面法线不受进动控制。[物理假设 + 下表实测支持]

E1-A 窗口重算（只读，24 窗口 57,544 样本）[实测]：

| 量 | P10 | P50 | P90 |
|---|---|---|---|
| 实际轴倾角（rad） | — | 0.020 | 0.034 |
| 接触处碗面法线倾角（rad） | — | 0.035 | 0.056 |
| 实际倾斜方位 vs 目标倾斜方位（°） | 7.6 | 35 | 92 |
| 摩擦方向 vs 相对倾斜预测方向（°） | 7.7 | 44 | — （均值 48） |
| 摩擦方向 vs 仅由轴倾斜预测（°） | — | 47 | — （均值 60） |
| 摩擦方向 vs 自然牵引方向（°） | — | 70 | — |

含义：可控部分（轴倾斜）比不可控部分（碗面法线）小，进动偏置能改变的只是相对倾斜里较小的那一项。[物理假设，由数据支持]

## 3. Muse 原始 E5 设计遗漏的代码前提

（未见 Muse 原文，以下根据 E5 任务描述推断其假设。）

1. **authority 不是独立物理通道**：它只是牵引门内进动调制的系数，门外完全不被消费（第 482 行）。[代码证据]
2. **针尖永远在门外**：gearGrip 0.1 < driveMinGrip 0.2，除脱困、墙边外没有例外。确认僵持恰好把这两种例外都排除了。[代码证据]
3. **僵持中的意图状态大多 authority ≈ 0**：观测确认僵持中状态分布为 roam 101,057 / guard 99,648 / contact 17,154 / disengage 12,910 / cut 913 / orbit 496；roam 的 a = 0。authority P50 0.0275、P90 0.129、最大 0.31。也就是说，即使门是开的，“下限”实际上是在凭空制造 authority，而不是放大已有意图。[实测 + motionIntent.ts 第 463 行代码证据]
4. **heading 在僵持中并不指向对手**：heading 与对手方位夹角 P50 118°、P10 5°、P90 177°（guard 回中心、disengage 背离对手）。借用 intent.heading 做方向偏置，偏的方向不是“去接触”，而是混合了各状态的目标。[实测]
5. **进动调制本身有约 80° 方向滞后**（第二轮修正时已测，见 autonomous-movement-v2）以及上表 35° 的倾斜跟随误差：即使链路接通，方向偏置也不会 1:1 变成运动方向。[实测（历史）]
6. **调制最大平均偏向只有 (1−√(1−a²))/a**（第 525–526 行注释）：a = 0.3 → 约 0.15，a = 0.6 → 约 0.33，且这是相位时间占比的偏向，不是力。[代码证据（公式）]

## 4. A / B / C 三条路径的可行性比较

定义：
- **A**：在门外（或独立于门）给 `rate` 乘一个只在确认僵持中非零的偏置因子 `1 − b·cos(Δ)`，Δ 为自然牵引方向与某个偏置方向之差，b < 1。
- **B**：在确认僵持中直接改进动相位（加相位偏移 / 锁定相位）或改目标倾斜向量（方向或 lean 大小）。
- **C**：保持使用 `intent.authority`，把第 482 行的读取（和第 527 行的调制）移到门外，使针尖也能消费 authority。

| 维度 | A：独立进动转速偏置 | B：相位 / 目标倾斜偏置 | C：authority 移出牵引门 |
|---|---|---|---|
| 作用的物理变量 | `precession` 的积分速率（第 524–538 行之间） | `precession` 值本身，或目标向量 (tx,ty,tz)（第 548–550 行） | 同 A（rate），但强度来自 intent.authority |
| 直接改线速度？ | 否（只影响 setAngvel 的 px/pz）[代码证据] | 否 [代码证据] | 否 [代码证据] |
| 间接产生水平力？ | 是，经轴倾斜方向 → 接触点 → Rapier 摩擦；量级受 μλ 封顶 [物理假设] | 是，且可比 A 更集中（锁定方向时摩擦方向长期不变）[物理假设] | 同 A [物理假设] |
| 改 Rapier 摩擦参数？ | 否；只改摩擦方向的来源（倾斜方位）[代码证据] | 否；但若改 lean 大小则改变接触偏移量，即摩擦力矩臂 [物理假设] | 否 [代码证据] |

### 4.1 路径 A 的有效性上限（为什么不能强行推荐为方案）

- 平均偏向上限 (1−√(1−b²))/b，b = 0.6 时约 0.33。[代码证据（公式）]
- 进动转速对倾斜的跟随存在相位滞后：自稳 ω_n ≈ √320 ≈ 17.9 rad/s，ζ ≈ 0.89，进动约 3–4 rad/s，二阶系统估算约 20° 滞后；实测倾斜跟随误差 P50 35°、历史测得调制方向滞后约 80°。[物理假设 + 实测]
- 碗面法线（不可控）比轴倾斜（可控）大：偏置只改较小的分量。[实测]
- **速度上限假设**：当线速度接近自转滑移速度（僵持中 P50 约 0.10 m/s）时，摩擦会转而阻碍运动；加上滚动阻力 0.448 m/s²（E1 实测），偏置可能最多把针尖带到与它自然漂移同量级的速度，而不足以“走出”碗底。[物理假设，未验证]
- 以上相乘，最乐观估计也只是把已有的约 0.1 m/s 漂移的方向在时间平均上偏一部分，能否引发重新接触不确定。[未验证]

## 5. 推荐入口

- **若架构决定继续验证“方向偏置能否经进动影响针尖运动”这一作用链：唯一可接受的诊断入口是路径 A**，原因：
  1. 只改一个量（进动积分速率），不改线速度、不加冲量、不改摩擦参数、不改牵引门；
  2. 相位永不锁死（b < 1），倾角大小不变，不触碰 knockResync / Wobble 的判定输入；
  3. 门控可用 hash 证明对非僵持、非针尖对针尖场景零影响（E5 已有 312/312 的验证框架）。
  - 入口位置：第 524 行算出自然 `rate` 之后、第 532 行 launch 分支之前，在诊断路径（不改 src/ 的包装或独立诊断构建）中乘因子，且 breakout > 0 时为 0。
- **不推荐把 A 作为修复方案**：上一节的有效性上限意味着它很可能“作用链存在但效果微弱”。如果下一版实验证实这一点，结论应是“进动方向偏置不足以解决针尖僵持”，而不是继续加大强度——加大到 b → 1 就变成锁相，即路径 B 的风险。
- **B 与 C 不推荐**：B 的风险（锁相出界、异常倾斜、改变 Wobble 与判定输入）已有历史实测；C 不独立，且僵持中 authority 本身约为 0，方向又与对手无关。

## 6. 可能引入的新物理风险（针对路径 A）

1. 单向持续漂移撞墙：偏置方向若固定朝某点，针尖可能以低速持续漂向外圈；门外无 edgeHelps 校验。[物理假设]
2. 僵持退出边界的不连续：门控在 3 s 停留后切入、速度 ≥ 0.4 时切出，可能出现切入 / 切出抖动（limit cycle）。[物理假设]
3. 能量账：A 不付 steerSpinCost；若架构认为改变倾斜方向应耗转速，需要另定，这会成为第二个变量。[代码证据 + 物理假设]
4. 跨平台 / 种子敏感：physics.test 有不固定 Math.random 的用例，A 的门控如果误触发，会被这些用例放大。[实测（历史）]
5. 对重新接触后的冲突：偏置把双方拉回接触后，若立即解除，可能出现反复“接近—接触—僵持”的周期，而不是自然运动（R1c 已见类似现象）。[实测（历史）+ 物理假设]

## 7. 下一版诊断实验应如何隔离变量（仅设计，未实施，需授权）

1. **只有一个自变量**：偏置强度 b ∈ {0, 0.3, 0.6}；偏置方向必须预先固定并写明（例如“自然牵引方向朝向对手方位”），不得借用 intent.heading（它在僵持中与对手方位 P50 差 118°，会把意图状态混进来）。方向定义本身是新的控制变量，需要架构先批准。
2. **门控与 E5 相同**（针尖对针尖、两者速度 < 0.4、spinRatio ≥ 0.4、无脱困、wobbleFor = 0、miss > 6、停留 ≥ 3 s），breakout > 0 时 b = 0。
3. **隔离证明**：b = 0 组与 Stage A 180/180 hash 相同；b > 0 组在非针尖对针尖的 156 场 hash 与 b = 0 相同；只有门控打开过的场次允许不同。
4. **逐环测量链路**，每一环独立给出数据，才能区分“哪一环失效”：
   - 环 1：rateOverNatural 偏离 1 的分布（应与 b 对应）；
   - 环 2：目标倾斜方位 vs 实际倾斜方位误差（应保持在基线 35° 附近，不得变大）；
   - 环 3：相对倾斜（轴 − 碗面法线）的方位在时间平均上是否偏向偏置方向；
   - 环 4：摩擦冲量方向（用 E1 的 Δv 反推法，法向冲量 ×8/9 修正）是否随之偏转；
   - 环 5：水平速度方向与幅度、离开僵持所需时间、重新接触率。
5. **安全指标**（作为停止条件，不作为优化目标）：最大倾角、是否触发 knockResync、是否接近墙（r > backoffEdge）、出界数、`tilt > 1.1` 次数、自转衰减速率与 b = 0 的差。
6. **能量账单独列出**：b > 0 时自转衰减是否高于 b = 0（如果不高，说明水平动能确实来自已存在的摩擦功，而不是注入）。
7. 不调整种子、不筛选场景，24 场针尖对针尖全报。
