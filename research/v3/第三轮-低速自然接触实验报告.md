# 第三轮自主运动实验：关闭通用僵持脱困（低速自然接触）

- 日期：2026-11-07（UTC）
- 分支：`feat/autonomous-bey-movement-v3`，从 `0c30c09338ed81c2e4d594f8e746018e1a7bddf6` 精确建立（建立时工作区干净；`feat/autonomous-bey-movement-v2` 与 `main` 未改动）
- 证据等级：**[实测]** = 本轮无头模拟直接测得（Rapier 120 Hz、固定种子，不是真机）；**[推断]** = 由实测或代码推出；**[未知]** = 本轮无法确定
- 结论先说：**[实测]** 只关通用僵持后，低速接触确实变长、程序性拉开基本消失，0 超时 0 出界；但**针尖对针尖的配置在高转速阶段会隔一条小缝停在碗底原地静止 35–87 秒**，physics.test 的 P2.3.1 僵持用例因此失败。按本轮规则（“关闭机制会破坏其他必要功能就先停止报告，不擅自设计替代机制”），我在这里停下，没有做任何补救性修改。**不建议现在进入真机 IPA 测试。**

## 0. 三份报告与任务摘要的差异（只列出，未改结论）

1. **统计范围**：摘要写“通用脱困触发后 0.5 s 接触比例降至 0”“69% 的触发直到比赛结束未再接触”。诊断报告第 3 节这两个数是**全部 85 次触发**（含 16 次 death wobble）的统计，不是只算 69 次通用僵持。
2. **本轮 B 配置以前没测过**：摘要中的“双关后 106 场 0 超时”“LONG 41.11 s 贴靠”都是**两种脱困同时关闭**（报告里的 C）。报告里的 B 是“只关 death wobble”。本轮“只关通用僵持、保留 wobble”在报告里没有数据。报告的 A/B/C 与本轮 A/B 命名冲突，下文写作“报告-B / 报告-C”。
3. **“根本没有物理接触”的口径**：报告的接触是几何近似（中心距 < 刀刃半径和 + 0.05），不读 Rapier 接触点。72% 的含义是“刀刃间隙 > 0.05”。
4. **原始数据起初不可得**：报告所在的 `research_notes/…`、`breakoutprobe.diag.ts`、`analyze-bp.mjs` 不在仓库和共享文件夹。本轮先按报告第 0 节重写探针并在 A 上复现报告数字（第 4.1 节）；之后用户补发了原始数据包，复核见第 4.6 节。
5. **本轮不处理的其他原因**：诊断报告 7.3 节与映射审查第 5、6 节指出，除通用僵持外还有接触意图的向外偏置（slideAway 0.8）、脱离后的切回决策、死亡阶段本身很短（刮地衰减、finishOf）。本轮按要求都不动。
6. **报告未提到的一项（本轮新发现）**：报告-C 的 LONG 组“平均 36.83 s、0 超时”我完全复现了，但其中 `LONG S/S#0` 一场打了 **96.6 s**，其中 **87 s 双方水平速度都 < 0.2 m/s**、隔约 0.09 停在碗底、接触只占 10%。“0 超时”只是因为它在 120 s 上限前以 spin 结束。报告的 41.11 s 贴靠（S/S#1）也是在**高转速**开始（转速比约 0.9–1.0），不是低速死亡阶段。
7. 小的表述差异：映射审查称脱困“不加冲量”，代码实际是每个物理步 `applyImpulse`（即持续施力，效果等同牵引力，不是一次性冲量），不影响结论。

## 1. 实施前检查（五个问题）

### 1.1 通用僵持的完整触发条件 [实测：读代码]
`src/game/battle/BattleSystem.ts` `watchStall()`（第 188 行起，`postStep` 每个物理步调用，dt = 1/120 s）：
- 双方水平速度都 < 0.8 m/s
- 中心距 < 两台**外缘**半径和 + 0.4（约 1.4；不要求接触，允许约 0.4 的缝隙）
- 双方转速都 > 10 rad/s
- 以上连续成立 > `stallTime` 0.6 s（任一帧不满足立即清零）
- 没有冷却，不受 `wobbleBreak` 开关控制

### 1.2 触发后改了什么 [实测：读代码]
- `stallFor = 0`，`breakouts++`
- **双方** `bey.breakout = 0.7`，双方 `intent.forceBreakout(0.7)`（意图进入 `breakout` 状态）
- 之后 0.7 s 内 `BeyPhysics.preStep`（第 439–500 行附近）：咬合度至少 0.35、牵引方向改为“背离对手再偏 0.9 rad”（离中心 > 2.0 去掉朝外分量）、速度上限与加速度按转速比 ≥ 0.8 计算、意图调制 `steering = 0`；仅在转速 > 14 rad/s、接地、未冲刺时生效
- 意图 `breakout` 满 0.7 s → `disengage` → 重新决策
- 副作用：触发期间 `high.breakout > 0` 使 death wobble 判定 `highInBreakout` 为真，`wobbleFor` 被清零

### 1.3 其他依赖 [实测：grep]
- `BeyPhysics.breakout`、`intent.forceBreakout` 也被 **death wobble 分支**使用（本轮保留，未改）
- `stallFor`：只有 `watchStall` 自己写；`tests/contact.test.ts` 用例 7 读它做统计
- `breakouts`：诊断/统计在 `tests/motion/motionSim.ts`、`tests/diag/motion.diag.ts`、`determinism.diag.ts`、`contact.test.ts`、`scripts/motion-compare.mjs` 读取；**游戏运行时没有任何代码依赖它**
- `tests/feelSim.ts` 有一个同名但独立的“僵持”统计（自己算，不读 BattleSystem）

### 1.4 关闭后是否留下累积状态 [实测]
不会。实现方式是让 `stalled` 恒为假，所以 `stallFor` 每步被置 0（探针每场结束时记录 `stallForEnd`，B 配置 146 场全部为 0）；`breakouts` 只会因 death wobble 增加；`bey.breakout` 只由 wobble 设置，并照常倒计时。

### 1.5 测试覆盖 [实测]
- 有：`contact.test` 用例 7（脱困与接触反馈兼容）、`physics.test`「P2.3.1 不会长时间原地互转」（最长僵持 < 1.6 s）、`motion.test` 的 `isDeathWobble` 判定测试
- 没有：直接验证“通用僵持关闭后不再触发”的单元测试；无接触时程序性拉开的检测（本轮用探针补上，作为诊断，不是回归测试）

## 7. 比赛观感（[推断]，基于模拟数据与录像，未经真机）

- 低速贴靠是否自然：球头对球头、攻击对防御的低速段，B 里贴靠变长、没有突兀拉开，漂开后 29% 在 1 s 内重新接触，方向上更接近视频里的“轻触—漂开—再接触”。
- 是否仍有程序性拉开：主矩阵里只剩终局前的 wobble（12 次），触发时对局实际已结束，观感影响 [未知]，估计很小。
- 是否出现无意义长时间静止：**是**。针尖对针尖在高转速下长时间隔缝静止，不属于视频里的“低速死亡阶段长贴靠”（那时双方接触且接近停转），而是 P2.3.1 的老问题回来了。球头对球头的 3–7 s 近静止属于中低转速、约一半时间接触，是否算“自然” [未知]，需要看录像和真机判断。
- 对抗感与节奏：中强撞 /10 s 下降约 7%（3.50 → 3.24），平均对局 +1.15 s；LONG 组下降更多（1.44 → 0.91）。
- 终局形态：A 有 6/106 场输家以大倾斜（> 1 rad）结束，B 为 0/106，全部是直立停转。原因 [未知]（可能是 A 里脱困牵引在低转速时推动摇摆方），视频里两种终局都有，这一项 B 反而离视频更远。

## 8. 仍然存在的问题与未知项

1. **[实测] 针尖对针尖高转速隔缝静止**（35–87 s）。通用僵持在 0c30c09 里实际承担了“让无牵引的针尖动起来”的功能。关闭它就会破坏这项功能，所以本轮在此停下，没有自己设计替代机制。
2. **[实测] B ≈ 报告-C**：保留 death wobble 在这个矩阵里几乎没有作用，它只在终局最后一刻触发。它是否该保留、阈值是否合理，不在本轮范围。
3. **[实测] 死亡阶段接触 16%，仍远低于视频约 50–87%**；死亡阶段时长 3.7 s。诊断报告指出的另一半原因（死亡阶段短、接触意图外推、切回决策）本轮没动。
4. **[未知]** 球头对球头 3–7 s 近静止在真机上看起来是“自然贴靠”还是“卡住”。
5. **[未知]** 真机帧率、触控发射力度对上述比例的影响；本轮全部是无头模拟。
6. **[未知]** 终局侧翻形态从 6 → 0 的原因。

需要你们决定的问题（我只列出，没有实现）：
- 针尖隔缝静止该怎么处理？例如通用僵持是否只对“不接触且高转速”的情况保留，或者用别的方式处理无牵引轴心，或者接受针尖对局本身就是慢的。这些都是新规则，需要架构评审。
- P2.3.1 的「最长僵持 < 1.6 s」用例是否还代表要求：它和“允许自然长贴靠”的新目标正面冲突。

## 9. 是否建议进入真机 IPA 测试

**不建议现在进入。** 理由：[实测] 针尖对针尖会出现 35–87 s 的原地静止，这在真机上会直接表现为“对局卡住”，而且有一条现有回归测试失败。建议先就第 8 节的两个问题做决定，再决定是否打包真机测试。如果你们只想在真机上看球头/攻击型配置的低速接触观感，这个分支本身可以打包，但需要你们明确接受针尖对局的问题。
